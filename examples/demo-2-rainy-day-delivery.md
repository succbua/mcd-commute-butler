# 示例二 · 暴雨天改外送

## 场景

午休前暴雨，不想出门取餐。从「到店取餐」切换为「麦乐送」，
配送费与送达耗时都要重新计入决策。

## 复现命令

```bash
node scripts/plan-commute-order.mjs --input examples/payload-delivery.json
```

## 这个结果说明了什么

**1. 配送费进入价格轴，改变了最优解。**
到店取餐场景下「美式咖啡单点」是最优（¥9）。加入 ¥9 配送费后，
单点饮品的边际成本被放大 —— ¥12 的咖啡花 ¥9 配送费并不划算。

于是引擎把推荐切换成了「玉米杯 + 美式咖啡」这个 ¥23 的组合：
多花 ¥6 商品钱，但把 ¥9 配送费摊到了两件商品上，同时**用掉了 ¥12 的券**，
最终实付 ¥20 —— 比单点美式（¥18）只多 ¥2，却多了一杯饮品。

这正是"配送费摊薄"这个真实决策逻辑被量化后的结果。

**2. 耗时维度自动换成「预计送达」。**
外送场景下 `deliveryEtaMinutes` 替代了到店排队时间，标签也从「最快取餐」变成「最快送达」。

**3. 券的门槛仍按商品金额判定。**
`满 20 减 12` 的门槛算的是商品小计（¥23），不是含配送费的总额（¥32）。
这与优惠券的通行规则一致 —— 配送费不计入门槛。

## 对应的 MCP 调用

外送场景需把门店查询换成配送侧工具：

```
delivery-query-addresses   → 已有收货地址（无则 delivery-create-address）
delivery-query-stores      → 该地址附近的可配送门店
query-meals                → 门店菜单
calculate-price            → 含配送费的官方计价口径
create-order               → 用户确认后下单
```
