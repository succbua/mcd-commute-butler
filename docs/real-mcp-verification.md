## 2. 实测发现的四处偏差（均已修正代码）

真实调用暴露了四个问题，全部与"照文档想当然"有关。

### 2.1 官方文档说 30 个工具，实际 35 个

官方仓库 README 的「工具列表」列了 30 个，实测服务端返回 **35** 个。
多出的包括 `query-promotions`（团餐促销）与 `query-survey-coupon`（按订单号查问卷券）。

### 2.2 `query-nearby-stores` 不接受地址字符串

最初按直觉传 `{"address": "上海市浦东新区世纪大道100号"}`，服务端返回：

```json
{"success": false, "code": 400, "message": "缺少参数", "traceId": "f1f44e35ef343c825ee76559fc9bb30e"}
```

实测正确参数为：

| 参数 | 必填 | 取值 |
|---|---|---|
| `beType` | ✅ | `1` 到店自提 / `5` 得来速车道取餐 |
| `searchType` | ✅ | `2` 按位置搜索 / `1` 搜索收藏餐厅 |
| `city` | — | 城市名 |
| `keyword` | — | 关键词 |

完整参数表见 [`../reference/mcp-tool-schemas.md`](../reference/mcp-tool-schemas.md)。

### 2.3 供应时段是门店级的，且与常识不同

**这是最重要的一条。** `query-nearby-stores` 返回的门店对象里带有
`reservationTimeOptions[].reservationOptionText`，即该门店**真实的**可预约时段。

实测麦当劳上海世纪汇广场餐厅（`storeCode: 1450253`）：

```
2026-10-09：夜市(17:14至21:45)
2026-10-10：早餐(07:14至10:15)，午餐(10:44至14:15)，下午茶(14:44至16:45)，夜市(17:14至21:45)
```

三点结论：

1. **真实早餐窗口是 07:14–10:15**，而本项目原先硬编码的估算表写的是 05:00–10:30 —— 差了将近 2 小时。
2. **不同门店不一致**。同一批返回中，上海浦东潍坊路餐厅的早餐从 `06:44` 开始。
3. **时段之间存在空档**。10:15 早餐结束，10:44 午餐才开 —— 中间 29 分钟属于**什么都买不到**的空档期。

因此本项目改为：**优先使用 `resolveStoreWindows()` 从 MCP 返回结果解析真实时段，
仅在拿不到时回退到估算表**，并在输出中标注时段来源（`[门店实时时段]` / `[估算时段]`）。
对空档期新增 `nextWindowAfter()`，直接告诉用户「下一时段 10:44 开始」。

### 2.4 真实优惠券是「品类级兑换券」，不是「满 X 减 Y」

`query-store-coupons` 真实返回：

```json
{
  "title": "麦旋风任选",
  "couponId": "71F939A874735C2495517B8B24323CFB",
  "couponCode": "MCD6F2Y2090L00Y190V76",
  "tradeDateTime": "2026-10-05 10:30:00-2026-10-09 23:59:59",
  "products": [{ "productCode": "9900014239", "productName": "麦旋风任选1" }]
}
```

两个关键点：

- **券的结构里没有 `discount` / `minSpend` 字段** —— 它是"免费兑换指定商品"的**兑换券**，
  抵扣额等于该商品的售价。本项目原先的 `满减券` 模型与真实数据对不上，已新增 `voucher` 类型。
- **`productCode` 不在门店菜单里**。实测 `9900014239` 未出现在该门店菜单的 key 中，
  但菜单里确实有「经典麦旋风」「蓝莓爆爆珠麦旋风」等 —— 说明这是**品类级「任选」券**。

**处理方式**：精确编码匹配才计入抵扣；品类关键词只用于**提示**，不自动计价。
猜错品类会导致报价错误，比不抵扣更糟。见 `findVoucherHints()`。

## 3. 真实门店与菜单

`query-nearby-stores`（`beType=1, searchType=2, city=上海市, keyword=世纪大道`）返回 5 家门店，最近一家：

| 字段 | 值 |
|---|---|
| `storeCode` | `1450253` |
| `storeName` | 麦当劳上海世纪汇广场餐厅 |
| `address` | 世纪大道1192号世纪汇广场LG1层 A01商铺 |
| `distance` | 72 米 |
| `businessStartTime` / `EndTime` | 06:30 / 22:00 |
| `reservation` | true |

`query-meals`（`storeCode=1450253, beType=1, orderType=1`）返回 **107 个餐品、15 个分类**。

> **实测旁证**：采集时间是 18:22（夜市时段），返回的菜单里**没有任何早餐品类**
> （无麦满分、无早餐分类）。也就是说 `query-meals` 只返回**当前时段可售**的餐品。
> 这直接印证了本项目的核心论点：**供餐时段是可售性的硬约束**，
> 不是"到了再挑"的问题，而是"菜单里根本不会出现"。

`list-nutrition-foods` 返回 **160 项**营养数据（能量、蛋白质、脂肪、碳水、钠、钙）。
本项目只取 `energyKcal` 作为热量筛选参数，不做任何营养建议。

## 5. 未调用的工具

以下工具本项目**不调用**，以免产生副作用或超出通勤点单的范围：

| 工具 | 原因 |
|---|---|
| `auto-bind-coupons` | 会实际写入用户账户，需用户单独同意 |
| `draw-lottery` | 消耗积分，与通勤点单无关 |
| `mall-create-order` | 扣减积分，不可逆 |
| `party-order-create` | 主题活动预约，非通勤场景 |
| `cancel-order` | 仅在用户明确要求取消时调用 |

## 6. 局限说明

- 本记录中的**优惠券**来自该 Token 所属账号的真实券包，其中两张均于 2026-10-09 23:59:59 到期。
  它们未参与计价，原因是其品类（麦旋风、薯薯）不在本次拉取的当前时段菜单中 —— 见 2.4 节。
- 未执行任何 `create-order` 调用，**没有产生任何真实订单**。
